# Инференс openTPU: вычисления, QuestaSim и движение данных

> **Как на самом деле идёт инференс** — `../../doc/inference.md`. **Потактовая
> картина настоящего RTL с программой LFM2.5-230M** — `../lens/README.md` (Lens).
> Этот каталог — учебная событийная модель и побитовый стенд одного MXU.

## Проверка комплекта (20.10.2026)

Комплект был проверен повторным запуском и сверкой с upstream RTL/компилятором.

- Воспроизводимость: `run_demo.sh` — exit 0 за 14 с, MXU 40/40 FP32 побитно
  (M=1 и M=4, N=8, K=384), подавлены только 5 диагностик 7061
  (`initial` + `always_ff` в generic RAM upstream).
- `tb_mxu.sv` — ценная часть: настоящий `otpu_mxu`, отказы grant, задержка
  чтения, проверка дублей. Покрыт только режим UNIT (без масштабов и offsets,
  FP4, PAIR, ACC/ASCALE/RMAX).
- `tb_llm_replay.sv` ничего не вычисляет: он воспроизводит время событий
  MATLAB-модели как сигналы для окна волн Questa. «N событий воспроизведено»
  проверяет только формат файла. Это иллюстрация, а не верификация.
- **Исправлены маршруты, противоречившие RTL** (`flow_route.m`,
  `prepare.py`, `llm_step.m`, `llm_profile.m`):
  - запись KV шла как FP32 «TMEM → HBM». В RTL это QST:
    TMEM → QUANT → HBM, INT8 + FP32-масштаб на токен и голову;
  - attention был «HBM → VPU → TMEM». В RTL `q·Kᵀ` и `P·V` — это MM на MXU,
    K-строки и Vᵀ-тайлы стримятся из HBM как веса, а на VPU идёт только
    softmax. Событие разбито на `attn_q_qact`, `attn_scores`,
    `attn_softmax`, `attn_p_qact`, `attn_pv`;
  - добавлен `logits_store` (ST логитов, их читает хост);
  - байты KV считает `otpu.kv_bytes`: строки K выровнены на D, Vᵀ — по байту
    на beat с RMW. Численно K/V теперь хранятся как INT8 с масштабом
    (`kvq` в `llm_step.m`); квантование q и P не эмулируется.
- Время модели оценочное (`max(HBM, вычисления)` на событие, без перекрытия).
  Для тактов используйте Lens: там LFM2.5-230M на RTL даёт 1,86–1,96 Мтакта на
  токен против 1,95 Мтакта на плате.
- Симулинк-генератор по-прежнему не запускался (MATLAB на стенде нет).

Начните с `out/llm_flow.html`: это автономный проигрыватель с выбором позиции
токена, паузой, шагами, подсветкой источника/получателя и объёмом HBM-трафика.
Он создаётся командой ниже; сервер и интернет для просмотра не нужны.

## Один запуск

Из корня репозитория:

```bash
vcu128_otpu/sim/inference/run_demo.sh
```

Нужны Octave, Python 3, QuestaSim (по умолчанию `$HOME/questasim/bin`), лицензия
Questa и доступный графический backend Octave для сохранения PNG.
Скрипт сначала выполняет численные проверки, затем декодер и графики, экспорт
трассы, два стенда Questa. Ошибка любого шага даёт ненулевой код.
Все промежуточные файлы, библиотеки и логи Questa находятся в `out/`;
результаты численного расчёта — в соседнем `../matlab/out/`.

## Что именно моделируется

| Уровень | Реализация | Что проверяется / ограничения |
|---|---|---|
| Численный LLM | `../matlab/+otpu/llm_step.m` | Полный небольшой LLaMA-подобный декодер: GQA, RoPE, RMSNorm, SwiGLU, residual, KV-cache, greedy generation. Случайные веса, без tokenizer/checkpoint Qwen/LFM. |
| Аппаратное ядро MM | `tb_mxu.sv` + upstream `otpu_mxu` | Настоящий RTL, D=128, MCOLS=4, LANES=8, INT8 UNIT, M=1/4, N=8, K=384. Все 40 FP32 результатов побитно проверяет отдельная тройная сумма signed INT8. |
| Полный поток операций LLM | `tb_llm_replay.sv` | Перенос 570 архитектурных событий численной модели в шкалу времени Questa. Это replay, не исполнение ISA/RTL декодера. |
| HBM | Численный учёт / модели интерфейсов | У LLM агрегированный трафик тензоров; у MXU синхронная модель ACT и чтения памяти. Реальный HBM IP, AXI, CDC и 40G не входят в этот стенд. |

Модель MXU использует generic arithmetic/RAM upstream, а не модель примитивов
DSP48E2. FIFO_DEPTH=32 вместо 1024: для трёх блоков достаточно, уменьшает
стенд. Таблица target не изменяется. Потактовая проверка всей программы
Qwen/LFM и загрузка её настоящих весов в Questa в этот комплект не входят.
Численная точность INT8 с offsets дополнительно проверяется `test_otpu`
на четырёх наборах upstream; этот RTL-стенд пока проверяет UNIT (scale=1,
offsets=0), без FP4, ACC, RMAX, ASCALE, replay M>MCOLS и QACT RTL.

Адрес `b_addr` MXU измеряется в **32-битных словах**; CSV пишет байтовые адреса.
`t_waddr` измеряется в FP32 словах. Чтение памяти имеет задержку четыре
регистра до видимого `b_rvalid`; grants чтения отключаются каждый пятый такт,
TMEM — каждый седьмой. Контроллер выдаёт результаты только при `t_gnt`.
Стенд проверяет отсутствие дублей/пропусков и имеет watchdog.

### Совместимость с Questa 2024.1

`questa_compat.py` создаёт `out/mxu_questa.sv`: делает массив связей `wc`
сетью, а регистры следующих колонок — отдельными локальными регистрами.
Это обходит конфликт портовых и процедурных драйверов элементов массива
(vsim-3839). Версионируемая копия upstream остаётся неизменной; генератор
проверяет наличие ожидаемого фрагмента и прекращает работу при его изменении.
Компиляция задаёт `-svinputport=net`. Только диагностике 7061 для
инициализации generic RAM и её `always_ff` задано suppress; численные
сравнения и `$fatal` не подавляются.

Reset держится 64 такта, и `t_gnt=1` во время reset: нересетируемые линии
задержки метаданных и RMW должны успеть заполниться. Короткий reset или
запрет grant во время reset приводили к X в FIFO/counters в четырёхзначной
симуляции; стенд не скрывает X приведением к двум состояниям.

## Графический режим Questa

```bash
vcu128_otpu/sim/inference/run_questa.sh --gui
vcu128_otpu/sim/inference/run_questa.sh --replay-gui
```

Первый режим: группы COMMAND, HBM→FIFO→MXU, ACT→MXU, MXU→TMEM.
Второй: имя операции, слой, позиция токена, источник/получатель, байты HBM.
Коды узлов: 0 HBM, 1 TMEM, 2 QUANT, 3 ACT, 4 MXU, 5 VPU.
`source/destination` описывают концы маршрута; весь маршрут виден в HTML.
GUI режим оставляет окно открытым, пакетный режим проверяет PASS и завершает
процесс. Сохранённые волны: `out/mxu.wlf`, `out/llm.wlf`.
`out/mxu_flow.csv` содержит принятые запросы чтения весов и фактические записи
результатов; это небольшой журнал проверяемого RTL-эксперимента.

## MATLAB / Octave / Simulink

В MATLAB или Octave:

```matlab
addpath('vcu128_otpu/sim/matlab');
test_otpu;
r = run_flow(true, 0.12);   % расчёт, затем анимация по операциям
% run_flow(false) сохраняет статический llm_flow.png без окна
```

Для MATLAB + Simulink дополнительно:

```matlab
model = build_flow_simulink();
sim(model);
```

Генератор создаёт `../matlab/out/otpu_llm_event_flow.slx`: From Workspace,
Demux и 8 Scope (активность HBM/TMEM/QUANT/ACT/MXU/VPU, байты чтения/записи).
Данные сохраняются в MAT и загружаются `InitFcn` при повторном запуске.
Это dashboard/replay рассчитанной трассы; численное вычисление LLM остаётся
в MATLAB-функциях. Самостоятельная вычислительная модель из Simulink-блоков
не заявляется. MATLAB/Simulink на этом стенде не найдены, генератор SLX
подготовлен, **его выполнение не проверено**. Численная модель и анимационный
кадр проверены Octave 8.4.0; идентичность RNG MATLAB/Octave не предполагается.
Подробности арифметики, оценки времени и регрессий — `../matlab/README.md`.

## Какие ещё способы полезны

- **Lens** (`../lens/`) — настоящий RTL слайса и настоящая программа модели: анимированная схема блоков, таймлайн, каждая инструкция со строкой исходника. Это основной инструмент для разбора движения данных.
- HTML/SVG из этого комплекта — простейший вход для объяснения алгоритма:
  быстро, пошагово, без установки MATLAB/Questa, но время оценочное.
- Questa Wave — для отладки реального RTL: запросы, grants, FIFO и значения.
  Visualizer при наличии соответствующей лицензии полезен для перехода от
  сигнала к исходнику и трассировки драйверов.
- MATLAB — для изменения размеров, чисел и исследования KV/HBM;
  Simulink dashboard — для наблюдения временных сигналов и расширения модели.
- GTKWave/Surfer с VCD — вариант обмена волнами без лицензии Questa;
  это просмотр сигналов, а не автоматическая схема тензорных потоков.
- Следующий уровень точности — полный RTL `otpu_slice` с программой ISA и
  сравнением с `Machine`, затем ко-симуляция HBM и калибровка по трассам платы.
  Для Qwen3.5/LFM нужно моделировать их конкретные attention/recurrent-блоки,
  форматы весов и программы, а не переносить эту LLaMA-схему без изменений.
